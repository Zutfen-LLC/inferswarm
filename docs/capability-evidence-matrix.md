# Capability evidence matrix

This page binds InferSwarm's mission language to the code that exists and the
records that were accepted. It is **explanatory and subordinate**: the
[living status record](project-status.json), the ADRs, the
[Fabric Doctrine](architecture/fabric-doctrine.md) and the linked maintainer
decisions control. Nothing here records an acceptance or grants execution
authority, and a physical observation is never read as either.

Audit basis (2026-10-09): InferSwarm `main@c2f0396cbff20ac0c5c7ddda3412ffad43a6db26`; FreeToken
[`inferswarm-research@6202eee`](https://github.com/Zutfen-LLC/FreeToken/tree/6202eeebcdf63e7bc8bb3498dd3c364ae42ee469).
Physical claims are bound to the accepted scope named in the row. Where a row
says "bounded to", the limit is part of the claim.

## Classes

| Class | Meaning |
|---|---|
| `IMPLEMENTED_AND_PHYSICALLY_PROVEN` | Shipped in this repository as an ordinary operator surface, with a recorded maintainer acceptance of physical evidence for it. |
| `CPU_OR_FIXTURE_PROVEN` | Implemented and proven only by deterministic CPU, fixture or loopback tests. No physical integration. |
| `RESEARCH_INTERNAL` | Real execution, usually with accepted physical evidence, but through research harnesses or evidence tooling (FreeToken `inferswarm-research`, `scripts/`, `tools/`) whose structures are explicitly not public planner, strategy, scheduling or wire APIs. |
| `ASPIRATIONAL_OR_UNPROVEN` | Not demonstrated, or observed without acceptance, or an open question. |

## Keeping this page honest

- Edit the [status record](project-status.json) first for any accepted
  capability, then regenerate with `python3 scripts/finalize_repository.py
  --write` (see [status maintenance](status-maintenance.md)). This page may only
  cite a physical result under an acceptance or decision it links.
- A new row that claims a physical result must name its accepted scope. A result
  with no recorded acceptance belongs in `ASPIRATIONAL_OR_UNPROVEN`, with its
  observation stated as an observation.
- `tests/test_project_status.py` guards the class names, the link from the
  README, and that every `IMPLEMENTED_AND_PHYSICALLY_PROVEN` row cites an
  acceptance comment.
